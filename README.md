# Stacks

Stacks is a consolidated media-tracking webapp — one place to search, rate, log, and list everything you
watch, read, play, and listen to. Think Letterboxd (movies/TV) + Goodreads (books) + RateYourMusic (music)
+ MyAnimeList (anime/manga) + a games tracker, combined.

## Technology stack

- **Frontend**: Vite + React 18 + TypeScript (strict) + Tailwind CSS + React Router + TanStack Query
- **Backend**: AWS Amplify Gen2 — Cognito (auth), AppSync/DynamoDB via Amplify Data, Amplify Functions
- **Hosting**: AWS Amplify Hosting (`amplify.yml` pipeline-deploy)

## Getting started

```bash
npm install

# Backend secrets needed before `ampx sandbox` will deploy successfully:
npx ampx sandbox secret set TMDB_API_KEY   # https://www.themoviedb.org/settings/api
npx ampx sandbox secret set RAWG_API_KEY   # https://rawg.io/apidocs
# (Google Books, MusicBrainz, Jikan, and the Letterboxd/Goodreads/RYM import all work keyless.)

npx ampx sandbox      # deploys a personal backend sandbox and generates amplify_outputs.json
npm run dev           # in a second terminal
```

`amplify_outputs.json` is generated by `ampx sandbox`/deploy and is gitignored. A placeholder copy exists
locally purely so `tsc`/`vite build` can resolve the import without a live backend — replace it by running
`ampx sandbox` for a real deploy.

## Scope and roadmap

This is a large, phased rehaul. Current state:

- **Phase 0/1 (done)**: full data schema (media catalog, library entries, diary, lists, follows, activity
  feed, likes/comments — see `amplify/data/resource.ts`), Cognito auth with a themed `Authenticator`,
  first-login username selection, and the full route skeleton.
- **Phase 2 (done)**: catalog search + media detail + library status/rating, live for all five categories —
  Movies/TV (TMDB), Books (Google Books), Music (MusicBrainz + Cover Art Archive), Anime/Manga (Jikan), and
  Games (RAWG).
- **Phase 3 (diary/reviews — done)**: log entries with a half-star rating, review text, date, spoiler and
  rewatch flags. Every user's log entries for a title show on its media page, like a reviews tab.
- **Phase 4 (lists — done)**: create lists (ranked or unranked), add items via the same catalog search,
  reorder with up/down, remove items. Visiting `/u/:username/lists` shows anyone's lists; only the owner
  gets edit controls.
- **Phase 5 (social — done)**: follow/unfollow from any profile, an activity feed at `/feed` showing
  followed users' diary logs/new lists/new follows, and likes on diary entries.
- **Phase 6 (import — done)**: `/import` lets you paste a Letterboxd, Goodreads, or RateYourMusic profile
  URL. Letterboxd uses its public RSS feed (reliable); Goodreads/RateYourMusic scrape public pages
  (experimental — ported from the `MediaParser` reference project, and will break if those sites change
  their markup). Nothing is added automatically — `/import/:jobId` is a manual match-and-confirm review step.

All six phases from the original plan are implemented and pass `lint`/`build`/`test`. Remaining known gaps,
by design (not oversights):
- No logged-out browsing — "public" visibility means visible to any signed-in Stacks user, not the open
  internet (Amplify Data's owner-auth can't do true per-row public ACLs without a Lambda authorizer).
- `/u/:username/library/:mediaTypeSlug` and `/u/:username/diary` (a user's full per-category library/diary
  browsing views) and `/settings` are still stub routes.
- Amplify Storage is provisioned for avatar/banner uploads but has no UI wired to it yet.
- No comments on diary entries (likes only) — the `Comment` model exists in the schema for a future pass.
